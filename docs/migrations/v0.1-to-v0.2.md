# Migrating from v0.1 to v0.2

- **Applies to consumers of:** `Wolfgang.Extensions.String` v0.1.x → v0.2.0
- **Deprecation window:** v0.1.x gets no further releases.
- **Trusted publisher / signing:** no change to how a release is verified. Releases after 0.1.1 also carry a build-provenance attestation; see [SECURITY.md](../../SECURITY.md#verifying-a-release).

## Summary

`ToCamelCase`, `ToKebabCase`, `ToPascalCase` and `ToSnakeCase` now find the words of a string by one shared rule, so the same input can give a different result than it did in v0.1. No public member was removed or renamed, and code compiled against v0.1 still binds: `AssemblyVersion` stays `1.0.0.0`. The work is to check every place where the result of one of the four conversions is stored, compared or used as a key. For most code bases that is a few minutes.

## Breaking-change inventory

| # | What changed | Why | Symptom on upgrade |
|---|---|---|---|
| 1 | Every character that is not a letter or a number is a word boundary and is left out of the result. That covers punctuation, symbols, control characters, `_` and `-`. | One rule for all four conversions ([ADR-0006](../adr/0006-one-word-splitter-for-the-case-conversions.md)). | A result has no punctuation where it had some: `"hello, world!".ToSnakeCase()` is `hello_world`, was `hello,_world!`. |
| 2 | An apostrophe is removed without ending the word. | `don't` is one word. | `"don't stop".ToSnakeCase()` is `dont_stop`, was `don't_stop`. |
| 3 | A word starts at a case boundary inside an identifier: at an upper-case letter after a lower-case letter or a number, and at the last upper-case letter of a run that a lower-case letter follows. | The conversions ran the words of an identifier together; that was a bug. | `"UserLoginCount".ToSnakeCase()` is `user_login_count`, was `userlogincount`. `"userLoginCount".ToPascalCase()` is `UserLoginCount`, was `Userlogincount`. `"iPhone".ToSnakeCase()` is `i_phone`, was `iphone`. |
| 4 | `ToSnakeCase` and `ToKebabCase` put exactly one delimiter between words and none at the ends. | Leading, trailing and repeated white space each produced a delimiter. | `"  two  words  ".ToSnakeCase()` is `two_words`, was `__two__words__`. |
| 5 | `ToCamelCase` and `ToPascalCase` treat `_` and `-` as word boundaries. | Same rule as item 1; snake and kebab input now converts. | `"user_login_count".ToPascalCase()` is `UserLoginCount`, was `User_login_count`. |
| 6 | A word that follows punctuation is capitalized by `ToCamelCase` and `ToPascalCase`. | A leading `(` or `"` used up the "start of word" position. | `"(hello) world".ToPascalCase()` is `HelloWorld`, was `(hello)World`. |
| 7 | `PadCenter` declares its receiver as `string`, not `string?`. | The method throws `ArgumentNullException` for `null`; the annotation now says so. | Source only: a nullable-aware caller that passes a maybe-null string gets warning CS8604. Nothing changes at run time. |
| 8 | `ToTitleCase` throws `ArgumentNullException` with `ParamName` `s`. | It came from `TextInfo` with `ParamName` `str`. | Code that inspects `ParamName` sees `s`. |
| 9 | The .NET Framework 4.6.2 and .NET Standard 2.0 builds depend on the `System.Memory` package (4.6.3). | The conversions build a short result on the stack ([ADR-0008](../adr/0008-system-memory-on-the-older-targets.md)). | A .NET Framework application that already references another version of `System.Memory` may need a binding redirect. The .NET 8 and .NET 10 builds still have no dependencies. |

## Before / after

### 1, 2 and 6. Punctuation is dropped

**Before (v0.1):**

```csharp
using Wolfgang.Extensions.String;

var snake = "hello, world!".ToSnakeCase();
// snake == "hello,_world!"
```

**After (v0.2):**

```csharp
using Wolfgang.Extensions.String;

var snake = "hello, world!".ToSnakeCase();
// snake == "hello_world"

// To keep the punctuation in the words, as v0.1 did:
var options = new CaseConversionOptions
{
    Punctuation = PunctuationHandling.Keep,
    Boundaries = WordBoundaries.Separators,
};

var kept = "hello, world!".ToSnakeCase(options);
// kept == "hello,_world!"
```

### 3. Identifiers are split at case boundaries

**Before (v0.1):**

```csharp
using Wolfgang.Extensions.String;

var snake = "UserLoginCount".ToSnakeCase();
// snake == "userlogincount"
```

**After (v0.2):**

```csharp
using Wolfgang.Extensions.String;

var snake = "UserLoginCount".ToSnakeCase();
// snake == "user_login_count"

// To leave an identifier as one word:
var options = new CaseConversionOptions { Boundaries = WordBoundaries.All & ~WordBoundaries.CaseChanges };

var oneWord = "UserLoginCount".ToSnakeCase(options);
// oneWord == "userlogincount"
```

### 4. One delimiter between words

**Before (v0.1):**

```csharp
using Wolfgang.Extensions.String;

var snake = "  two  words  ".ToSnakeCase();
// snake == "__two__words__"
```

**After (v0.2):**

```csharp
using Wolfgang.Extensions.String;

var snake = "  two  words  ".ToSnakeCase();
// snake == "two_words"
```

There is no option that brings the repeated delimiters back.

### 5. Underscores and dashes divide words in camel case and Pascal case

**Before (v0.1):**

```csharp
using Wolfgang.Extensions.String;

var pascal = "user_login_count".ToPascalCase();
// pascal == "User_login_count"
```

**After (v0.2):**

```csharp
using Wolfgang.Extensions.String;

var pascal = "user_login_count".ToPascalCase();
// pascal == "UserLoginCount"
```

### 7. `PadCenter` takes a non-nullable string

**Before (v0.1):**

```csharp
using Wolfgang.Extensions.String;

string? maybe = GetName();

var padded = maybe.PadCenter(20); // compiles without a warning, throws when maybe is null
```

**After (v0.2):**

```csharp
using Wolfgang.Extensions.String;

string? maybe = GetName();

var padded = (maybe ?? string.Empty).PadCenter(20);
```

## Non-breaking additions (informational)

- `CaseConversionOptions`, with an overload of each of the four conversions that takes it: keep punctuation, choose what divides words, leave acronyms in upper case, or supply your own word splitter ([ADR-0007](../adr/0007-options-overloads-and-a-custom-word-splitter.md)).
- `SplitWords`, which returns the words of a string by the same rules.
- The `net8.0` and `net10.0` assets are marked trimmable and Native-AOT compatible.
- The package no longer ships a 4.3 MB icon file and no longer asks you to accept its licence on install.

## Deprecation timeline

- **v0.1.1** is the last version with the old word rules.
- **v0.2.0** changes them. Patch releases of v0.2 will not bring the old results back; use `CaseConversionOptions` where you need them.
